# ChestLink

ChestLink 是一个纯服务端 Fabric 模组，可以把多个原版箱子加入同一个命名频道。频道内的所有箱子使用同一份 27 格库存，箱子界面、漏斗、投掷器和比较器都会读写这份库存。

本文档也有 [English](README.md) 版本。

## 功能

- 共享库存。同一频道的成员直接读写同一个物品列表，不在多个库存之间复制物品。
- 跨维度连接。一个频道可以包含不同维度的箱子，其中一个成员所在区块未加载时，其他成员仍可正常使用。
- 兼容原版客户端。模组不添加方块、物品、方块实体或客户端资源，原版客户端可以直接加入安装了 ChestLink 的专用服务器。
- 持久保存。频道物品和成员位置随世界保存。
- 支持原版自动化。漏斗、投掷器、容器界面和比较器都会使用共享库存。

## 安装

在服务器安装 Fabric Loader，并把 Fabric API 和 ChestLink JAR 放进 `mods` 目录。客户端不需要安装 ChestLink 或 Fabric API。单人游戏需要把它们安装到本地游戏实例，因为单人游戏的内置服务器运行在客户端进程中。

## 命令

命令需要 2 级权限。执行 `link` 或 `unlink` 时，需要看向五格内的箱子。

```text
/chestlink link <channel>
/chestlink unlink
/chestlink list
```

频道不存在时，`link` 会创建频道，并用当前箱子里的物品初始化共享库存。加入已有频道时，目标箱子必须为空。

`unlink` 会移除目标箱子。频道仍有其他成员时，物品留在频道内，被移除的箱子变为空箱。移除最后一个成员时，频道物品回到该箱子，随后删除频道。

`list` 会列出全部频道，以及每个成员的维度和坐标。

只能连接没有未开启战利品表的单箱，陷阱箱也可以使用。破坏已连接箱子时会执行与 `unlink` 相同的规则。破坏非最后成员不会掉落频道物品，破坏最后成员会掉落频道库存。

## 存储

频道数据保存在 `<world>/data/chestlink/links.dat`。箱子加入频道后，其私有库存会被清空，正常库存操作会转向频道。卸载模组后，原版不会读取频道数据文件。如果需要让物品继续可用，请在卸载前解除所有连接。

## 构建和测试

```bash
./gradlew test
./gradlew runGameTest
./gradlew build
```

构建产物位于 `build/libs/`。JUnit 测试不需要运行世界的逻辑，Fabric GameTest 在测试服务器中验证共享库存、mixin 和连接生命周期。GitHub Actions 会运行两类测试并上传构建产物。

## 已知限制

- 每个频道固定为 27 格，不会随箱子数量增加。
- 不能连接大箱子。在已连接箱子旁放置另一个箱子时，原版仍可能把它们合并成大箱子，产生不受支持的 54 格界面。
- 箱盖动画和开启人数分别由每个箱子维护。
- 对已连接箱子执行 `/data` 会修改它的私有库存，不会修改当前频道库存。
- 第三方模组如果绕过正常方块移除流程删除箱子，可能不会触发自动解除连接。
